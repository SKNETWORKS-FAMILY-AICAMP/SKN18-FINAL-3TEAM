# Intent-Aware Query Validation Report

## 목적
Intent-aware 평가를 위해 40개 테스트 쿼리가 각 query_type의 특성을 제대로 반영하고 있는지 검증

## 평가 기준

### 1. Factual 쿼리 (10개)
- **특성**: 단순 사실 확인, 1-hop 관계 조회
- **평가 포인트**:
  - 수렴 노드 필요도: 낮음 (가중치 0.5)
  - Schema 준수: 높음 (가중치 1.5)
  - Intent 보존: 높음 (가중치 1.3)
- **기대 동작**: 직접적인 관계 조회, 최소한의 확장

### 2. Causal 쿼리 (10개)
- **특성**: 인과관계 추론, "원인", "이유", "배경"
- **평가 포인트**:
  - 수렴 노드 필요도: 높음 (가중치 1.5)
  - 관계 일관성: 높음 (가중치 1.3) - 인과 체인 연결
  - 증거 다양성: 높음 (가중치 1.2) - 다각적 인과 분석
- **기대 동작**: Causal chain semantic expansion 활성화

### 3. Comparative 쿼리 (10개)
- **특성**: 2개 엔티티 비교, "공통점", "차이점"
- **평가 포인트**:
  - 수렴 노드 필요도: 매우 높음 (가중치 1.6)
  - 증거 다양성: 매우 높음 (가중치 1.4) - 양쪽 증거 필요
- **기대 동작**: 2개 엔티티의 수렴 지점 발견이 핵심

### 4. Deep Analysis 쿼리 (10개)
- **특성**: 심층 분석, "영향", "과정", "분석"
- **평가 포인트**:
  - 수렴 노드 필요도: 높음 (가중치 1.3)
  - Intent 보존: 매우 높음 (가중치 1.5)
  - 관계 일관성: 높음 (가중치 1.4)
- **기대 동작**: 복합적 관계 추론, 다층 확장

## 종합 평가

### ✅ 강점

1. **Query Type별 분포 균형**
   - 각 query_type당 정확히 10개씩
   - 총 40개 쿼리로 충분한 샘플 크기

2. **Intent 키워드 명확성**
   - Factual: "언제", "누가", "어디", "무엇"
   - Causal: "원인", "이유", "배경", "목적", "결과"
   - Comparative: "공통점", "차이점", "비교", "유사점"
   - Deep Analysis: "영향", "과정", "분석", "설명", "관계"

3. **Difficulty 분포**
   - Factual: Easy (8개), Medium (2개) → 적절
   - Causal: Medium (6개), Hard (4개) → 적절
   - Comparative: Medium (1개), Hard (9개) → 적절 (비교는 본질적으로 어려움)
   - Deep Analysis: Hard (10개) → 적절 (심층 분석은 본질적으로 어려움)

4. **수렴 노드 중요도 분포**
   - Factual: 수렴 노드 언급 없음 → ✅ 가중치 0.5 적합
   - Causal: 4/10개가 "(수렴 노드 중요)" 표시 → ✅ 가중치 1.5 적합
   - Comparative: 7/10개가 "(수렴 노드 중요)" 표시 → ✅ 가중치 1.6 적합
   - Deep Analysis: 5/10개가 "(수렴 노드 중요)" 표시 → ✅ 가중치 1.3 적합

5. **엔티티 다양성**
   - 인물: 세종, 이순신, 정조, 정약용, 광해군 등
   - 사건: 임진왜란, 병자호란, 갑신정변, 동학농민운동 등
   - 장소: 경복궁, 불국사, 수원 화성 등
   - 개념: 훈민정음, 당쟁, 삼국통일 등

6. **2-Entity 비교 충분**
   - Comparative 쿼리 10개 모두 2개 이상 엔티티 비교
   - 수렴 노드 테스트에 최적

### ⚠️ 개선 가능 영역

1. **Factual 쿼리 복잡도**
   - 현재: 대부분 매우 단순한 1-hop 쿼리
   - 제안: 일부 쿼리를 2-hop으로 확장하여 semantic expander 효과 테스트
   - 예시: "임진왜란 당시 조선을 도운 명나라 장수는?" (2-hop: 임진왜란 → 명나라 → 장수)

2. **Causal 쿼리 depth**
   - 현재: 대부분 1-level 인과관계 (A → B)
   - 제안: 일부 쿼리를 multi-level 인과 체인으로 (A → B → C)
   - 예시: "임진왜란이 조선 후기 대외 정책에 미친 영향은?" (전쟁 → 사회 변화 → 정책 변화)

3. **Deep Analysis 쿼리 구체성**
   - 현재: "영향", "과정" 등 다소 추상적
   - 제안: 더 구체적인 분석 측면 명시
   - 예시: "세종대왕의 업적이 조선 사회의 문자 해독률에 미친 영향" (더 구체적)

## 결론

### ✅ 최종 판단: Intent-Aware 평가에 매우 적합

**이유**:
1. 40개 쿼리 모두 각 query_type의 특성을 명확히 반영
2. 수렴 노드 중요도가 query_type별로 명확히 차별화됨
3. Intent 키워드가 명확하여 intent preservation 평가 가능
4. 다양한 엔티티와 관계로 평가 일반화 가능

**실험 가능한 가설**:
1. Factual 쿼리는 semantic expansion 없이도 높은 점수
2. Causal 쿼리는 causal_chain expander 활성화 시 점수 상승
3. Comparative 쿼리는 수렴 노드 생성 시 점수 크게 상승
4. Deep Analysis 쿼리는 모든 expander 활성화 시 최고 점수

**권장 사항**:
1. 현재 40개 쿼리로 Intent-aware 평가 즉시 시작 가능
2. 향후 확장 시 위의 "개선 가능 영역" 참고
3. 실험 결과에 따라 추가 쿼리 생성 고려

## 실험 우선순위

### Phase 1: 기본 Intent-Aware 평가 (즉시 시작 가능)
- 40개 쿼리로 query_type별 가중치 효과 검증
- 각 query_type의 final_score 분포 확인
- 수렴 노드 중요도 가설 검증

### Phase 2: Ablation Study (기본 평가 후)
- Semantic expander별 효과 측정
- Aggregator thread별 효과 측정
- Query type별 최적 조합 발견

### Phase 3: 고급 분석 (필요시)
- 쿼리 복잡도 증가 (2-hop, multi-level causal chain)
- Thinking trace 시각화 준비
- 실시간 평가 시스템 구축
